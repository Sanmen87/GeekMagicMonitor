# Разработка и подготовка Git

## Компоненты

`monitor/GeekMagicMonitor` — WinForms, настройки, датчики, погода и предпросмотр.
`GeekMagicMonitor.Core` — модели экранов, команды, HTTP-клиент, разбор погоды.
`GeekMagicMonitor.SensorAgent` — отдельный повышенный сборщик CPU.
`GeekMagicMonitor.Tests` — консольные автоматические проверки без стороннего test runner.
`firmware/src` — ESP8266: config, Wi-Fi, веб/API, LCD и локальные часы.

Версия исходников — VERSION; прошивка при наличии Git использует git describe,
а из ZIP берёт VERSION. Зависимости .NET закреплены packages.lock.json,
PlatformIO/библиотеки прошивки — конкретными версиями в platformio.ini.

## Проверки и сборка

```powershell
dotnet run --project .\monitor\GeekMagicMonitor.Tests -c Release
.\build_monitor.ps1
.\build_firmware.ps1
```

Проверяются 304 варианта экранов на русском и английском, отсутствие наложений/выхода за области
перерисовки, лимиты JSON/команд, изменения кадров, пропущенные датчики, погода,
часовые пояса, retry/ack/heartbeat и наличие Content-Length до отправки.
Также проверяются миграция настроек с локализованных названий на стабильные ID,
сохранение языков, проверка поддержки кириллицы прошивкой.
Сохранение отправки проверяется записью и повторной загрузкой настоящего файла
настроек для обоих состояний; смена языка не сбрасывает этот флажок.
33 русские буквы и UTF-8 декодер проверяются static_assert при сборке прошивки.
Для сборки прошивки требуется подготовленная `.venv`, см. FIRMWARE.md.

Офлайн-предпросмотр и проверка настоящего окна:

```powershell
.\artifacts\monitor\GeekMagicMonitor.exe --export-preview .\.local\preview
.\artifacts\monitor\GeekMagicMonitor.exe --smoke-test .\.local\window.png
.\artifacts\monitor\GeekMagicMonitor.exe --smoke-test-en .\.local\window-en.png
.\artifacts\monitor\GeekMagicMonitor.exe --export-preview-ru .\.local\preview-ru
```

Экспорт содержит PNG 480×480, варианты LCD-отражения и изображения 240×240.
Шрифт GDI схематичный; физическая читаемость проверяется на кубе.
Smoke-проверки переключают язык в настоящих контролах/меню трея, проверяют сохранение
выбора экрана/GPU/провайдера и не меняют пользовательские настройки.
На старте GUI уже присутствует отдельный экземпляр? Утилиты работают независимо
от него, обычный повторный запуск окна — нет.

```powershell
# Запрашивает внешний сервер погоды, но не рисует:
.\artifacts\monitor\GeekMagicMonitor.exe --diagnose-weather .\.local\weather.json

# Рисует на кубе из настроек! Только после проверки адреса и нашей прошивки:
.\artifacts\monitor\GeekMagicMonitor.exe --test-cube .\.local\cube.json
```

Сетевой тест отправляет реальные часы/погоду/метрики, проверяет полные и частичные
пакеты. HTTP-handler читает тело после отправки, чтобы журналирование не меняло
способ передачи. Иконка: SVG/ICO в Assets, регенерация `tools/make_icon.ps1`.

## Публикация исходников

`.gitignore` исключает локальные инструменты, `.local`, отчёты, BIN/EXE/архивы,
артефакты сборки и персональный config.json. Автотесты и шаблоны конфигурации
являются частью исходников. Сторонние уведомления и licenses также должны остаться.

```powershell
git init -b main               # Только если репозиторий ещё не инициализирован
git add .
python .\tools\check_repository.py
git diff --cached --stat
git diff --cached
git config user.name "ВАШЕ ИМЯ"
git config user.email "ВАШ EMAIL ИЛИ GITHUB NOREPLY"
git commit -m "Initial GeekMagicMonitor sources"
```

Проверка читает индекс Git: перед ней повторите git add после изменений.
Она ищет запрещённые файлы, личные пути, явные ключи и пароли в JSON-шаблонах;
это дополнительная проверка, а не замена просмотру diff.

После создания пустого удалённого репозитория без README/лицензии:

```powershell
git remote add origin URL_ВАШЕГО_РЕПОЗИТОРИЯ
git push -u origin main
```

Удалённый репозиторий проект автоматически не создаёт и ничего не публикует.
Для чистого ZIP набора, **включённого в индекс Git**, без коммита и личных файлов:

```powershell
.\tools\export_source.ps1
```

Проверке экспорта нужен Python 3: используется `.venv`, если она создана,
иначе команда `python` из PATH.

Результат в `artifacts/source/`. Изменения, не добавленные git add, в ZIP не попадут.
Сборки для Releases формируются отдельно: папка приложения, папка сборщика и
две прошивки, с лицензиями. Персональный LittleFS не распространяйте.

## Ограничения этой версии

API/OTA без авторизации, транспортный лимит тела на устройстве до буферизации
не реализован. Автономно работает время, погода зависит от ПК. Восстановление
AP→STA и взаимодействие ручных GIF-режимов не полностью автоматизированы.
Проверка одного куба не заменяет испытаний других плат и длительного прогона.
