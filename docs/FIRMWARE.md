# Сборка и установка прошивки

## Совместимость и сохранность данных

Профиль `esp12e`: ESP8266, Flash 4 МиБ, LittleFS 2072576 байт,
ST7789 240×240. Он испытан на одном HelloCubic Lite: обычный запуск,
домашний Wi-Fi, recovery AP, полные/частичные кадры и отражение через стекло.
Это не подтверждает совместимость всех устройств с тем же названием.

Перед первой заменой программы определите плату и возможность восстановления.
Полный дамп своего экземпляра полезнее скачанного заводского BIN: он содержит
разделы и настройки именно ваших часов. Не подключайте UART к неизвестным
контактам; логические уровни ESP — 3,3 В. Сохранённые дампы могут содержать пароли.
Автоматического скрипта резервного копирования в этом проекте нет.

Первый запуск и запись связаны с риском потери Wi-Fi. Recovery работает только
если сама программа загружается. При её отказе может понадобиться UART.

## Подготовить инструменты

Нужен Python с venv/pip (подойдёт 3.12 x64), интернет при первой сборке и
PlatformIO Core 6.2.0. Из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install platformio==6.2.0
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_firmware.ps1
```

Скрипт создаёт `firmware/data/config.json` из `config-hellocubic.example`,
если его ещё нет. Пароли по умолчанию пустые. Свой конфиг можно отредактировать
до сборки или затем настроить сеть через веб-интерфейс. Полный пример явно
задаёт использованные GPIO/SPI; физическая разводка других ревизий не измерялась.

Версии платформы и библиотек закреплены в platformio.ini. Инструменты и сборки
остаются локально в `.venv/`, `.platformio/`, `firmware/.pio/`, `artifacts/`.
Ни одна из команд сборки не загружает файлы в устройство.

Результат:

```text
artifacts/firmware/firmware.bin
artifacts/firmware/littlefs.bin
```

`firmware.bin` — программа: LCD, HTTP API, NTP и загрузчик обновлений.
`littlefs.bin` — полный образ раздела: конфиг, веб-интерфейс и загруженные файлы.
Замена LittleFS заменяет и настройки; перед повторным buildfs сохраните нужный
локальный config. Не публикуйте персональный образ с паролями.

## Первая загрузка со штатной прошивки

Подготовьте устройство с Wi-Fi и оба BIN заранее. После первого этапа куб
может исчезнуть из домашней LAN и создать собственную сеть. Компьютеру только
с Ethernet понадобится второе устройство или Wi-Fi адаптер.

1. Откройте `http://ТЕКУЩИЙ_IP/update` штатных часов.
2. В поле **Firmware** выберите наш `firmware.bin`. Подтвердите обновление,
   дождитесь завершения и перезапуска, не отключая питание.
3. Найдите сеть **GeekMagic**, пароль **`$str0ngPa$$w0rd`**.
4. Подключитесь к ней, оставаясь в сети без интернета. Откройте
   `http://192.168.4.1/` и `http://192.168.4.1/api/v1/device`.
5. Ожидается `application=GeekMagicMonitor`, `mode=recovery`, `accessPoint=true`,
   `flashRealBytes=4194304`, `flashConfiguredBytes=4194304`,
   `filesystemPartitionBytes=2072576`, `displayReady=false`.
   При несовпадении ёмкости текущий LittleFS не загружайте: нужен другой профиль.
6. Откройте `http://192.168.4.1/legacyupdate`. В разделе **FileSystem** выберите
   `littlefs.bin` из той же сборки и нажмите **Update FileSystem**.
7. После перезапуска подключитесь к GeekMagic снова. При пустых credentials
   откройте `http://192.168.4.1/wifi.html` и настройте домашнюю сеть 2,4 ГГц.
8. Найдите новый IP на автономном экране или в роутере. Подключите компьютер
   к той же LAN и откройте `http://НОВЫЙ_IP/api/v1/device`.
   Ожидается `mode=normal`, `accessPoint=false`, `displayReady=true`.
9. Укажите этот адрес в приложении Windows и включите отправку кадров.

До загрузки нашей файловой системы экран намеренно выключен: recovery не
трогает GPIO LCD. Для обычного запуска нужны читаемый config и файл
`/geekmagic-monitor.profile`; не удаляйте эту метку из образа.

При неопределённом результате обновления сначала проверьте устройство.
Повторная отправка файла автоматически не выполняется.

## Обновления и автономный режим

При работающем Wi-Fi `/legacyupdate` позволяет отдельно обновить Firmware
и FileSystem. Также есть веб-страница `/update.html`. Пустой/нечитаемый конфиг
или отсутствие нашей метки ведут в recovery; ошибки кода или аппаратуры этим
механизмом не исправляются гарантированно. Автоформатирование выключено.

Дисплей отражается с `lcd_rotation=4` для оптики проверенного куба. Параметры
часов: `clock_timezone=MSK-3` (POSIX), NTP по умолчанию pool.ntp.org с резервным
time.cloudflare.com. После холодного старта нужен доступ к NTP; без времени
показано TIME NOT SYNCED. Через 15 секунд без кадров — PC OFFLINE и локальные часы.
Погода автономно не загружается, кадры/метрики во Flash не записываются.

## API

`GET /api/v1/device` сообщает режим, адрес, размеры Flash/FS и готовность LCD.
Поле `cyrillicText=true` означает поддержку UTF-8 кириллицы в командах text.
ASCII и русские буквы рисуются в ячейке 6×8, масштабируемой параметром size.
Русские строчные буквы на LCD отображаются прописными; другие Unicode-символы
заменяются вопросительным знаком. Английские надписи совместимы с ранней прошивкой.
Для добавления кириллицы достаточно обновить Firmware, не перезаписывая FileSystem
с настройками Wi-Fi. Язык кадров задаёт приложение; локальные часы и веб остаются английскими.
`GET /api/v1/wifi/status` сообщает состояние сети.
Для рисования используется `POST /api/v1/draw/batch`:

```json
{"commands":[{"type":"clear","color":"#091321"},{"type":"text","x":12,"y":30,"size":3,"text":"HELLO","color":"#ffffff","bg":"#091321"}]}
```

Тело JSON должно передаваться с **Content-Length**, не chunked.
Лимиты: 1–64 команды, 8192 байт, текст до 128 байт, size 1–8.
Успех: `{"status":"ok","processed":2}`. Первый кадр и восстановление связи
требуют полной перерисовки; последующие обновляют отдельные области.

API и OTA пока без авторизации. Используйте доверенную локальную сеть
и не перенаправляйте порты устройства в интернет. Не все режимы GIF интегрированы
с автономными часами; основное назначение этой версии — экраны GeekMagicMonitor.
